# PHP AI Accelerators

Набор готовых акселераторов для AI-агентов в PHP-проектах и генератор для
создания такого акселератора по фактической структуре отдельного проекта.
Каждая редакция объединяет правила, команды, агентов, навыки, проверки
качества и соглашения по документации. Она не заменяет код, конфигурацию,
тесты и спецификации проекта.

## Что находится в репозитории

~~~text
AI-Infrastructure/
├── Laravel/                  # готовая Laravel-редакция
├── Symfony/                  # готовая Symfony-редакция
├── PHP Core/                 # готовая редакция для нативного PHP
└── Infrastructure-Creator/   # генератор под конкретный проект
~~~

- [Laravel/](Laravel/README.md) — готовая редакция для Laravel: Eloquent,
  очереди, события, уведомления, Filament и разработка пакетов.
- [Symfony/](Symfony/README.md) — готовая редакция для Symfony: практические
  границы Controller → Service → Repository, Doctrine, Messenger, API
  Platform, voters, Forms и Symfony UX.
- [PHP Core/](PHP%20Core/README.md) — нейтральная к фреймворку основа для
  Composer + PSR-проектов, PDO и явных границ приложения.
- [Infrastructure-Creator/](Infrastructure-Creator/README.md) — не готовая
  редакция для копирования, а генератор, который исследует целевой проект и
  создаёт подходящий набор правил для работы агентов.

Первые три каталога — самостоятельные готовые редакции.
Infrastructure-Creator/ решает другую задачу: создаёт новую редакцию по
составу, интеграциям, архитектуре и CI/CD указанного PHP-проекта.

## Как выбрать редакцию

| Редакция | Базовая платформа | Когда выбирать |
| --- | --- | --- |
| [Laravel/](Laravel/README.md) | Laravel 12 / 13, PHP 8.2+ (PHP 8.3+ для Laravel 13) | Проект уже использует Laravel, Eloquent, Artisan, Sanctum, очереди или экосистему Laravel. |
| [Symfony/](Symfony/README.md) | Symfony 7.4 LTS с PHP 8.2+ или Symfony 8.1 с PHP 8.4+ | Проект использует Symfony, Doctrine, Messenger, API Platform, voters и типичные Symfony-границы. |
| [PHP Core/](PHP%20Core/README.md) | Нативный PHP 8.2+ | Обычный PSR-проект, микрофреймворк или фреймворк без отдельной редакции. |

Если проект уже на Laravel или Symfony, берите соответствующий каталог. Для
остальных случаев подходит PHP Core/: он не навязывает ORM, роутер или
DI-контейнер.

## Как подключить акселератор к проекту

AI-инструменты начинают поиск своих файлов от корня рабочей области. Поэтому есть два
рабочих способа подключения:

1. Открыть каталог выбранной редакции как корень рабочей области и держать реальное
   приложение рядом с ним или внутри него.
2. Скопировать содержимое выбранного каталога — включая .claude/, .cursor/,
   .agents/, .codex/, AGENTS.md и документацию — в корень реального проекта.

Открытие корня этого монорепозитория само по себе не активирует вложенную
редакцию: Claude Code, Cursor и Codex не ищут конфигурацию автоматически в
Laravel/, Symfony/ или PHP Core/.

## Общая архитектура: Command → Agent → Skill

Все три редакции используют одну модель работы, адаптированную под стек:

~~~text
Запрос пользователя
        ↓
Command выбирает Agent
        ↓
Agent выполняет один Skill в изолированном контексте
        ↓
Результат, краткий контекст и следующие шаги
~~~

- Command направляет намерение пользователя в подходящий процесс.
- Agent остаётся тонкой оболочкой: запускает один навык и завершает работу,
  чтобы решение оставалось наблюдаемым и управляемым.
- Skill содержит сам процесс: проверки, примеры, критерии решений и формат
  результата.
- Перехватчики и файлы политик обеспечивают соглашения о безопасности, именовании и
  проверке результата.

В каждой редакции tasks/ содержит временные документы задач с префиксом навыка,
а specs/ — постоянные актуальные спецификации, зарегистрированные в
specs/MANIFEST.md.

В Claude Code и Cursor команда обычно выбирает агента. В Codex нет отдельного
слоя команд: навык вызывается по имени или выбирается самим Codex из
.agents/skills/.

## Поддерживаемые AI-инструменты

Каждая редакция зеркалирует процесс для трёх инструментов, чтобы их файлы не
конфликтовали:

| Инструмент | Читает | Практическое значение |
| --- | --- | --- |
| Claude Code | .claude/ | Исходная редакция с агентами, командами, перехватчиками, навыками и настройками. |
| Cursor | .cursor/ | Самостоятельное зеркало с навыками, командами, агентами, правилами и перехватчиками; загрузку .claude в Cursor нужно отключить, чтобы не загрузить правила дважды. |
| Codex | .agents/skills/ и .codex/ | Навыки находятся в .agents/skills/, а .codex/ содержит конфигурацию, перехватчики и справочные материалы; отдельного слоя команд нет. |

AGENTS.md выбранной редакции — исполняемая политика для её стека. Её README
содержит полный состав каталогов, предварительные требования, таблицы команд и
проверки.

## Чем отличаются редакции

Общий процесс одинаков, но добавляются только возможности реального стека:

- Laravel добавляет возможности для Filament, Eloquent, очередей задач,
  событий и уведомлений, настройки аутентификации, кэша, планировщика Artisan,
  хранения файлов и Composer/Laravel-пакетов.
- Symfony добавляет возможности для API Platform, миграций Doctrine,
  подписчиков событий, форм и проверки данных, правил авторизации, Messenger,
  консольных команд, тестовых данных, границ Controller/Service/Repository, DI-контейнера и
  Twig/Symfony UX.
- PHP Core сохраняет минимальную общую основу: архитектуру, API и БД, код,
  тестирование, проверку кода и безопасности, производительность, зависимости,
  отладку и выпуск версий без предположений о конкретном фреймворке.

Редакции не требуют синхронизировать все изменения механически: проверяйте,
имеет ли изменение смысл в конкретном стеке.

## Project Brain, Local Context Engine и Memory Bank

Каждая редакция объединяет три независимых компонента:

- **Project Brain — что происходит сейчас.** Это общий, хранящийся в Git
  авторитетный слой для активных задач и handoff-записей, а также findings,
  bugs, incidents, decisions и events. Записи содержат владельца, уровень
  приватности и авторитетности, отпечатки источников, ревизии, переходы
  жизненного цикла и явные конфликты.
- **Local Context Engine — как находятся релевантные источники.** Он индексирует
  допустимые политики, навыки, документацию и спецификации проекта, записи и
  handoff-файлы Project Brain, активные фрагменты Memory Bank и историю в
  игнорируемой SQLite-базе. При поиске применяются FTS5/BM25, фильтры
  приватности, авторитетности и актуальности, ограниченные фрагменты, бюджет
  токенов и retrieval manifests.
- **Memory Bank — что запоминается надолго.** Она хранит небольшие,
  зафиксированные в Git и прошедшие проверку фрагменты с многократно
  используемыми ограничениями, решениями, знаниями предметной области,
  интеграционными контрактами и операционными уроками.

По умолчанию используется governed mode. Общим состоянием активной работы
владеет Project Brain; `memory-bank/local/context.db` служит только одноразовым
индексом, локальной привязкой/кэшем и, при необходимости, источником
неавторитетных replay episodes. Удаление SQLite не удаляет записи Project
Brain, фрагменты Memory Bank или канонические источники проекта. Локальная
Working Memory, производная от имени ветки, существует только в явно
настроенном `--mode lightweight` для работы на одной машине.

### Авторитетность и доверие

Механизмы контроля, политики, актуальные спецификации, код, конфигурация,
миграции и тесты остаются каноническими и имеют приоритет над любым найденным
контекстом. Project Brain координирует текущую работу, но не переопределяет эти
источники. Memory Bank — проверенное долговременное знание, а не конкурирующий
источник истины. Найденные фрагменты служат только для обнаружения информации:
их нужно сверять с указанным актуальным источником.

Сырые диалоги, запросы и ответы, скрытые рассуждения, журналы, учётные данные,
секреты, клиентские или персональные данные и неочищенные материалы инцидентов
не должны попадать ни в одно из этих хранилищ. Игнорируемые, приватные,
недоступные, устаревшие, заменённые, завершённые или некорректные записи
исключаются там, где это применимо.

### Пользовательский процесс в governed mode

Для нетривиальной работы:

~~~text
запрос со стабильным task ID
    → создать или продолжить задачу Project Brain
    → обновить одноразовый индекс
    → получить ограниченный контекст с учётом задачи
    → проверить канонические источники
    → реализовать задачу и обновить задачу/handoff с проверкой ревизии
    → проверить результат и завершить задачу
    → при необходимости перенести одобренное человеком знание
    → архивировать завершённые записи
~~~

Полный пошаговый разбор приведён в
[примере пользовательского процесса](USER-TASK-WORKFLOW-EXAMPLE.md).

Публичная команда получения контекста в governed mode:

~~~bash
python3 memory-bank/scripts/context.py retrieve \
  "password session invalidation" \
  --task-id BAUMAS-133
~~~

`context` остаётся алиасом `retrieve` для совместимости; в новой документации и
автоматизации следует использовать `retrieve`. Индексация и поиск запускаются
явно. Hooks сообщают только метаданные — режим, состояние индекса, число
активных привязок и результат валидации; они не индексируют источники, не
выполняют поиск, не печатают записи и не внедряют контекст в запрос.

### Учитывающие авторитетность `memory` и `checkpoint`

Для обновления без аргументов вызовите `memory` в Codex или `/memory` в
Claude/Cursor. В governed mode команда проверяет Project Brain и обновляет
одноразовый индекс, не создавая задачу из имени ветки, не присваивая локальной
записи авторитетность задачи и не дублируя прогресс в SQLite.

Когда требуется сохранить прогресс, вызовите `checkpoint` в Codex или
`/checkpoint` в Claude/Cursor. В governed mode команда пропускает запись в
локальную Working Memory и направляет агента на обновление существующей задачи
Project Brain и её handoff с текущей ревизией. Только явно настроенный
lightweight mode может получить локальный идентификатор задачи из Git-ветки и
сохранить очищенный локальный снимок Working Memory.

Ни одна из этих команд не завершает задачу, не применяет promotion и не
изменяет отслеживаемые исходники проекта без явного действия.

### Явный CLI-процесс в governed mode

Запускайте команды из корня редакции или потребляющего проекта:

~~~bash
python3 memory-bank/scripts/context.py start \
  --task-id BAUMAS-133 \
  --goal "Проверить инвалидирование других сессий после смены пароля"
python3 memory-bank/scripts/context.py index
python3 memory-bank/scripts/context.py retrieve \
  "password sessions" \
  --task-id BAUMAS-133
python3 memory-bank/scripts/context.py update \
  --task-id BAUMAS-133 \
  --revision 1 \
  --progress "Регрессионный тест с двумя сессиями проходит" \
  --next-step "Проверить старый remember-me cookie"
python3 memory-bank/scripts/context.py complete \
  --task-id BAUMAS-133 \
  --revision 2 \
  --outcome "Другие сессии и устаревшие remember-me cookies инвалидируются" \
  --verification "ChangePasswordTest passed"
python3 memory-bank/scripts/context.py compact
~~~

Для изменений сразу в двух хранилищах governed mode использует проверку ревизии
и rollback/compensation, чтобы сбой Project Brain или SQLite не оставил
рассогласованное авторитетное состояние. Promotion выполняется отдельно: агент
может предложить многократно используемое знание с привязкой к источникам и
ревизиям, но перед атомарным переносом в Memory Bank его должен одобрить
независимый человек. Lightweight mode сохраняет прежний локальный цикл
`start → update → retrieve → complete` и локальные episodes; они неавторитетны
и теряются при удалении его SQLite-базы.

Реализация локальна, написана на Python без внешних зависимостей и использует
SQLite FTS5. В ней нет embeddings, vector search, MCP, LangGraph, центрального
сервиса памяти или автоматической подстановки контекста в каждый запрос.

## Infrastructure Creator

Infrastructure-Creator/ создаёт акселератор для конкретного целевого проекта,
а не заменяет готовые Laravel, Symfony или PHP Core редакции. Его держат вне
целевого проекта — в отдельной рабочей области или соседнем каталоге.

Поток работы: infra-scan → review → infra-generate. infra-scan только читает
целевой проект и ничего в него не записывает; он создаёт профиль проекта для
проверки. На этапе review можно исправить выводы. infra-generate записывает
акселератор только для выбранных AI-инструментов и перед перезаписью чего-либо
запрашивает подтверждение. Если отдельная проверка не нужна, infra-build
выполняет анализ и генерацию одним потоком, останавливаясь при неоднозначности
или конфликте.

Генератор исследует фактические composer.json, фреймворк, зависимости,
интеграции, архитектуру и CI/CD, а не копирует шаблон Laravel, Symfony или PHP
Core. Полная инструкция находится в
[Infrastructure-Creator/README.md](Infrastructure-Creator/README.md).

## Как внести изменения

- Меняйте навыки только в тех редакциях, где они действительно применимы;
  Laravel-исправление не автоматически относится к Symfony или PHP Core.
- Универсальное правило сначала оценивайте для PHP Core/, затем адаптируйте его
  к границам соответствующего фреймворка, а не копируйте без проверки.
- Внутри одной редакции зеркальте изменения навыков, агентов и команд между
  .claude/, .cursor/, .agents/ и .codex/ в объёме поддерживаемых инструментов.
- Зафиксируйте изменение в CHANGELOG.md соответствующей редакции и выполните
  её проверку из DOD.md.

Для деталей конкретного стека используйте README выбранной редакции. Для её
долговременной памяти открывайте соответствующий файл:
[памяти Laravel](Laravel/memory-bank/README.md),
[памяти PHP Core](PHP%20Core/memory-bank/README.md) или
[памяти Symfony](Symfony/memory-bank/README.md), а затем INDEX.md этой
редакции.
