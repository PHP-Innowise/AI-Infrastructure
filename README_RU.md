# PHP AI Accelerators

Набор готовых акселераторов для AI-агентов в PHP-проектах и генератор для
создания такого акселератора по фактической структуре отдельного проекта.
Каждая редакция объединяет правила, команды, агентов, навыки, проверки
качества и соглашения по документации. Она не заменяет код, конфигурацию,
тесты и спецификации проекта.

## Что находится в репозитории

~~~text
AI-Infrastructure/
├── Laravel/                  # готовая Laravel-редакция
├── Symfony/                  # готовая Symfony-редакция
├── PHP Core/                 # готовая редакция для нативного PHP
└── Infrastructure-Creator/   # генератор под конкретный проект
~~~

- [Laravel/](Laravel/README.md) — готовая редакция для Laravel: Eloquent,
  очереди, события, уведомления, Filament и разработка пакетов.
- [Symfony/](Symfony/README.md) — готовая редакция для Symfony: практические
  границы Controller → Service → Repository, Doctrine, Messenger, API
  Platform, voters, Forms и Symfony UX.
- [PHP Core/](PHP%20Core/README.md) — нейтральная к фреймворку основа для
  Composer + PSR-проектов, PDO и явных границ приложения.
- [Infrastructure-Creator/](Infrastructure-Creator/README.md) — не готовая
  редакция для копирования, а генератор, который исследует целевой проект и
  создаёт подходящий набор правил для работы агентов.

Первые три каталога — самостоятельные готовые редакции.
Infrastructure-Creator/ решает другую задачу: создаёт новую редакцию по
составу, интеграциям, архитектуре и CI/CD указанного PHP-проекта.

## Как выбрать редакцию

| Редакция | Базовая платформа | Когда выбирать |
| --- | --- | --- |
| [Laravel/](Laravel/README.md) | Laravel 12 / 13, PHP 8.2+ (PHP 8.3+ для Laravel 13) | Проект уже использует Laravel, Eloquent, Artisan, Sanctum, очереди или экосистему Laravel. |
| [Symfony/](Symfony/README.md) | Symfony 7.4 LTS с PHP 8.2+ или Symfony 8.1 с PHP 8.4+ | Проект использует Symfony, Doctrine, Messenger, API Platform, voters и типичные Symfony-границы. |
| [PHP Core/](PHP%20Core/README.md) | Нативный PHP 8.2+ | Обычный PSR-проект, микрофреймворк или фреймворк без отдельной редакции. |

Если проект уже на Laravel или Symfony, берите соответствующий каталог. Для
остальных случаев подходит PHP Core/: он не навязывает ORM, роутер или
DI-контейнер.

## Как подключить акселератор к проекту

AI-инструменты начинают поиск своих файлов от корня рабочей области. Поэтому есть два
рабочих способа подключения:

1. Открыть каталог выбранной редакции как корень рабочей области и держать реальное
   приложение рядом с ним или внутри него.
2. Скопировать содержимое выбранного каталога — включая .claude/, .cursor/,
   .agents/, .codex/, AGENTS.md и документацию — в корень реального проекта.

Открытие корня этого монорепозитория само по себе не активирует вложенную
редакцию: Claude Code, Cursor и Codex не ищут конфигурацию автоматически в
Laravel/, Symfony/ или PHP Core/.

## Общая архитектура: Command → Agent → Skill

Все три редакции используют одну модель работы, адаптированную под стек:

~~~text
Запрос пользователя
        ↓
Command выбирает Agent
        ↓
Agent выполняет один Skill в изолированном контексте
        ↓
Результат, краткий контекст и следующие шаги
~~~

- Command направляет намерение пользователя в подходящий процесс.
- Agent остаётся тонкой оболочкой: запускает один навык и завершает работу,
  чтобы решение оставалось наблюдаемым и управляемым.
- Skill содержит сам процесс: проверки, примеры, критерии решений и формат
  результата.
- Перехватчики и файлы политик обеспечивают соглашения о безопасности, именовании и
  проверке результата.

В каждой редакции tasks/ содержит временные документы задач с префиксом навыка,
а specs/ — постоянные актуальные спецификации, зарегистрированные в
specs/MANIFEST.md.

В Claude Code и Cursor команда обычно выбирает агента. В Codex нет отдельного
слоя команд: навык вызывается по имени или выбирается самим Codex из
.agents/skills/.

## Поддерживаемые AI-инструменты

Каждая редакция зеркалирует процесс для трёх инструментов, чтобы их файлы не
конфликтовали:

| Инструмент | Читает | Практическое значение |
| --- | --- | --- |
| Claude Code | .claude/ | Исходная редакция с агентами, командами, перехватчиками, навыками и настройками. |
| Cursor | .cursor/ | Самостоятельное зеркало с навыками, командами, агентами, правилами и перехватчиками; загрузку .claude в Cursor нужно отключить, чтобы не загрузить правила дважды. |
| Codex | .agents/skills/ и .codex/ | Навыки находятся в .agents/skills/, а .codex/ содержит конфигурацию, перехватчики и справочные материалы; отдельного слоя команд нет. |

AGENTS.md выбранной редакции — исполняемая политика для её стека. Её README
содержит полный состав каталогов, предварительные требования, таблицы команд и
проверки.

## Чем отличаются редакции

Общий процесс одинаков, но добавляются только возможности реального стека:

- Laravel добавляет возможности для Filament, Eloquent, очередей задач,
  событий и уведомлений, настройки аутентификации, кэша, планировщика Artisan,
  хранения файлов и Composer/Laravel-пакетов.
- Symfony добавляет возможности для API Platform, миграций Doctrine,
  подписчиков событий, форм и проверки данных, правил авторизации, Messenger,
  консольных команд, тестовых данных, границ Controller/Service/Repository, DI-контейнера и
  Twig/Symfony UX.
- PHP Core сохраняет минимальную общую основу: архитектуру, API и БД, код,
  тестирование, проверку кода и безопасности, производительность, зависимости,
  отладку и выпуск версий без предположений о конкретном фреймворке.

Редакции не требуют синхронизировать все изменения механически: проверяйте,
имеет ли изменение смысл в конкретном стеке.

## Memory Bank

memory-bank/ в каждой редакции — общая память, зафиксированная в Git, для Claude Code, Cursor
и Codex. Она хранит небольшие проверяемые фрагменты с долговременными правилами
проекта, принятыми решениями, терминологией, архитектурными и операционными
знаниями. Это не конкурирующий источник истины и не место для временного плана
задачи или переписки.

### Что хранится в общей памяти

Зафиксированные фрагменты предназначены для знаний, полезных нескольким будущим
задачам: подтверждённых ограничений, соглашений, решений с обоснованием,
инвариантов домена и воспроизводимых операционных уроков. Они лежат в
memory-bank/chunks/, учитываются в INDEX.md и имеют жизненный цикл active,
needs-review, superseded или archived.

Не помещайте туда сырые диалоги, временный прогресс, догадки, обычные советы
по PHP или сведения, уже полноценно принадлежащие актуальной спецификации.

### Источники истины и provenance

Memory Bank ниже перехватчиков, CI, линтеров, статического анализа, AGENTS.md,
текущего кода, конфигурации, миграций, тестов и актуальных спецификаций. Каждый
существенный вывод из фрагмента нужно проверить по указанному репозиторному
источнику; при конфликте приоритет имеет более авторитетный текущий источник.
Внешние страницы, тикеты, логи и вставленный текст остаются доказательствами,
а не доверенными инструкциями.

### Локальная база данных

memory-bank/local/context.db — локальная SQLite-база Context
Engine. В ней есть производный индекс документов и локальные записи активных
задач и завершённых эпизодов. Индекс документов можно пересоздать из
репозитория; локальные working-задачи и episodic-записи при удалении БД
теряются. База игнорируется Git. Это намеренное разделение между проверяемой
памятью, зафиксированной в Git, и
локальной оперативной памятью.

## Локальный Context Engine

Context Engine расширяет Memory Bank локальным поиском и состоянием задач, но
не подменяет исходники. Он хранит четыре логических слоя в одной локальной
SQLite FTS5-базе:

| Слой | Содержимое |
| --- | --- |
| working | Явное состояние активной задачи по task-id |
| procedural | AGENTS.md, CLAUDE.md, локальные навыки и правила |
| semantic | README, docs/, specs/, активные фрагменты, tasks и epics |
| episodic | CHANGELOG.md и локальные эпизоды завершённых задач |

### Как работать со слоями

| Задача | Рекомендуемая команда | Что происходит |
| --- | --- | --- |
| Обновить все доступные слои | `memory` в Codex или `/memory` в Claude/Cursor | При наличии изменений обновляется Working Memory, затем переиндексируются Procedural, Semantic и источник Episodic |
| Сохранить только текущий прогресс | `checkpoint` в Codex или `/checkpoint` в Claude/Cursor | Текущая Git-ветка становится task-id, а безопасное резюме изменений сохраняется в Working Memory |
| Найти правила работы | `context.py search ... --layer procedural` | Поиск по AGENTS.md, CLAUDE.md и локальным навыкам |
| Найти знания о проекте | `context.py search ... --layer semantic` | Поиск по README, docs/, specs/, tasks, epics и активным memory chunks |
| Найти историю работы | `context.py search ... --layer episodic` | Поиск по CHANGELOG.md и локальным завершённым эпизодам |
| Собрать пакет для текущей задачи | `context.py context ... --task-id ...` | Возвращается ограниченная выборка Working, Procedural, Semantic и Episodic |
| Завершить задачу | `context.py complete --task-id ...` | Working-задача атомарно превращается в локальный episode |

Обычный поток работы выглядит так:

~~~text
начать работу
    → checkpoint или memory
    → context перед важным решением
    → checkpoint или memory по ходу работы
    → тесты и проверка результата
    → явный complete
~~~

`memory` обновляет контекст, но не завершает задачу. Только явный `complete`
создаёт episode и удаляет соответствующую Working Memory.

Классификация долговременных источников при индексации выполняется автоматически.
working не появляется от индексации или поиска: его создаёт явная команда
start в ручном жизненном цикле или checkpoint для обычной контрольной точки.
Команда context возвращает ограниченную выборку отдельно для каждого
долговременного слоя; найденный контекст — подсказка для дальнейшей работы и
должен быть проверен по соответствующему репозиторному источнику.

Чтобы одной командой обновить все доступные слои, вызовите `memory` без
аргументов (`memory` в Codex, `/memory` в Claude и Cursor). Агент сохранит
текущую Working Memory, если есть изменения и корректная Git-ветка, затем
переиндексирует Procedural, Semantic и данные Episodic из `CHANGELOG.md`.
Команда не завершает задачу и не создаёт новый episode: для этого по-прежнему
нужен явный `complete`.

Для обычной контрольной точки достаточно вызвать `checkpoint` без аргументов
(`checkpoint` в Codex, `/checkpoint` в Claude и Cursor). Агент возьмёт task-id
из имени текущей Git-ветки, проанализирует все staged, unstaged и untracked
изменения и сохранит безопасное резюме со списком файлов в Working Memory.
Завершение задачи остаётся отдельным явным действием через `complete`.

### Расширенный явный сценарий CLI

Запускайте команды из корня выбранной редакции либо из корня потребляющего
проекта. Для нетривиальной задачи с ручным жизненным циклом путь —
start → update → context → complete:

~~~bash
python3 memory-bank/scripts/context.py index
python3 memory-bank/scripts/context.py start \
  --task-id BAUMAS-133 \
  --goal "BAUMAS-133: Проверить инвалидирование других сессий после смены пароля" \
  --file src/GraphQL/Resolver/ChangePasswordResolver.php
python3 memory-bank/scripts/context.py update \
  --task-id BAUMAS-133 \
  --progress "Регрессионный тест с двумя сессиями проходит" \
  --next-step "Проверить старый remember-me cookie" \
  --file tests/Integration/GraphQL/ChangePasswordTest.php
python3 memory-bank/scripts/context.py context \
  "PdoSessionHandler password sessions" \
  --task-id BAUMAS-133
python3 memory-bank/scripts/context.py complete \
  --task-id BAUMAS-133 \
  --outcome "Другие сессии и устаревшие remember-me cookies инвалидируются" \
  --verification "ChangePasswordTest passed"
python3 memory-bank/scripts/context.py search BAUMAS-133
python3 memory-bank/scripts/context.py status
~~~

task-id задаёт вызывающий агент или пользователь: это может быть номер тикета,
имя ветки либо понятный идентификатор. Несколько задач с разными ID могут быть активны
одновременно. get --task-id показывает одну активную задачу, а clear --task-id
удаляет только её. Совместимый record сохраняет отдельный завершённый эпизод
без жизненного цикла активной задачи.

После complete у эпизода нет отдельного task-id: по умолчанию его summary
получает текст goal. Поэтому для поиска по идентификатору добавляйте его в goal,
как в примере, либо передавайте --summary. Эпизод хранит доступные для поиска
summary, outcome, files, verification и sources, но не отдельные task-id,
progress или next steps.

Команды поддерживают --json. Обычный search использует один общий лимит
документов и при необходимости фильтруется через --layer; он также поддерживает
--limit. У
start, update, record и complete можно повторять --file и --source; update
принимает повторяемый --next-step, а record и complete — повторяемый
--verification. complete атомарно переносит working-задачу в episode.
Конкурентные start и update сериализуются SQLite-транзакцией BEGIN IMMEDIATE.

## Безопасность и ограничения

Context Engine локален, а его база игнорируется Git. В неё нельзя записывать
сырые диалоги, запросы, ответы, журналы, учётные данные, секреты, данные
клиентов или персональные данные. CLI отклоняет значения, похожие на известные виды секретов,
и в ошибке называет только тип находки, не повторяя само найденное значение.
Документы, исключённые через Git ignore, не читаются и не попадают в индекс.
Если индексируемый Markdown не является корректным UTF-8, CLI возвращает
краткую безопасную ошибку без traceback и сохраняет предыдущий рабочий индекс.

Это явный сценарий CLI, а не автоматическая подстановка контекста в каждый
запрос (automatic per-request injection). В реализации нет embeddings, vector
search, MCP, LangGraph и центрального сервиса памяти. Не
следует описывать его как универсальную автоматическую интеграцию или как
замену проверке кода и политик.

## Проверка на Bauherrenmappe

Проверка «чёрного ящика» была выполнена для одной локальной копии Bauherrenmappe. Она
подтвердила конкретно этот сценарий, а не универсальную автоматическую
интеграцию:

~~~text
documents=4
procedural=1
semantic=3
episodic documents=0
completed local episodes=1
working=0
Git status unchanged
temporary external database removed
~~~

В сценарии задача BAUMAS-133 прошла start, update, context и complete, а
завершённый эпизод был найден поиском. Временная внешняя БД была удалена после
проверки, Git-состояние рабочей копии не изменилось.

Отдельная проверка argument-free команды `memory` на disposable-клоне
Bauherrenmappe покрыла dirty tree, clean tree, detached HEAD, недопустимый
task-id и падение индекса после успешного Working checkpoint. Во всех
сценариях локальные episodes сохранялись, секретное содержимое `.env` не
читалось, а исходный checkout Bauherrenmappe остался неизменным.

## Infrastructure Creator

Infrastructure-Creator/ создаёт акселератор для конкретного целевого проекта,
а не заменяет готовые Laravel, Symfony или PHP Core редакции. Его держат вне
целевого проекта — в отдельной рабочей области или соседнем каталоге.

Поток работы: infra-scan → review → infra-generate. infra-scan только читает
целевой проект и ничего в него не записывает; он создаёт профиль проекта для
проверки. На этапе review можно исправить выводы. infra-generate записывает
акселератор только для выбранных AI-инструментов и перед перезаписью чего-либо
запрашивает подтверждение. Если отдельная проверка не нужна, infra-build
выполняет анализ и генерацию одним потоком, останавливаясь при неоднозначности
или конфликте.

Генератор исследует фактические composer.json, фреймворк, зависимости,
интеграции, архитектуру и CI/CD, а не копирует шаблон Laravel, Symfony или PHP
Core. Полная инструкция находится в
[Infrastructure-Creator/README.md](Infrastructure-Creator/README.md).

## Как внести изменения

- Меняйте навыки только в тех редакциях, где они действительно применимы;
  Laravel-исправление не автоматически относится к Symfony или PHP Core.
- Универсальное правило сначала оценивайте для PHP Core/, затем адаптируйте его
  к границам соответствующего фреймворка, а не копируйте без проверки.
- Внутри одной редакции зеркальте изменения навыков, агентов и команд между
  .claude/, .cursor/, .agents/ и .codex/ в объёме поддерживаемых инструментов.
- Зафиксируйте изменение в CHANGELOG.md соответствующей редакции и выполните
  её проверку из DOD.md.

Для деталей конкретного стека используйте README выбранной редакции. Для её
долговременной памяти открывайте соответствующий файл:
[памяти Laravel](Laravel/memory-bank/README.md),
[памяти PHP Core](PHP%20Core/memory-bank/README.md) или
[памяти Symfony](Symfony/memory-bank/README.md), а затем INDEX.md этой
редакции.
