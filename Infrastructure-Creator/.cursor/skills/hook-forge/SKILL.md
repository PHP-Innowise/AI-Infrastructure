# Hook Forge

## Overview

`hook-forge` writes the target project's deterministic guardrails and its automatic memory loop - eight shell hooks in three groups, plus the per-edition wiring that runs them:

- **Enforcement (4):** inject context, validate risky shell commands, enforce file-naming policy, and detect agent loops. Every enforcement hook is tuned to the target's REAL stack and risk surface from the profile, not a template: the danger list in `bash-validator.sh` contains only commands whose underlying tools were actually detected.
- **Working memory (2):** `working-memory-read.sh` (prompt-time: refresh every memory layer and emit a bounded task capsule) and `working-memory-write.sh` (turn-end: buffer the turn's change set and flush it to the authoritative task on a boundary). These are stack-agnostic thin callers of the runtime `memory-seed` installs at `memory-bank/scripts/context.py` - that path is a fixed contract between the two forges.
- **Subagent orchestration (2):** `subagent-gate.sh` restricts subagent spawning to the target's own generated roster; the host tool's built-in agents (Claude Code's Explore/Plan/general-purpose, Cursor's explore/bash/browser, Codex's spawn_agent roles) are denied, and agents whose frontmatter carries `writes: true` are serialized one at a time. `subagent-dispatch.sh` observes the other end: when a subagent finishes it appends a `completion` entry to the task's agent channel and releases that write lock. Unlike the six shared scripts, the gate is TOOL-OWNED: each edition gets a variant matching its host's contract - Claude reads `tool_input.subagent_type` and blocks with exit 2, Cursor answers `subagentStart` with `{"permission": "allow"|"deny"}` JSON, Codex denies the `spawn_agent` tool family outright (its edition delegates through skills and has no agent roster). The dispatch observer is one script in all three editions.

Hooks are generated ONLY for the selected editions under the required
generation root (task staging during orchestration), and each edition wires the
scripts through its own configuration mechanism. Stack/risk evidence is always
read from the real target; generated paths are resolved from staging.

Consumes profile sections **1** (which editions), **2** (stack/tooling for context + naming rules), **4** (integrations that widen the risk surface), **5** (infra/ops - the only source that authorizes infra danger rules), and **6** (security - secrets/destructive-op posture).

## Generated File Naming Convention (MANDATORY)

For each selected edition, into the target write the eight hook scripts under that edition's hooks dir (`.claude/hooks/`, `.cursor/hooks/`, `.codex/hooks/`): `local-context.sh`, `bash-validator.sh`, `file-naming-validator.sh`, `loop-detection.sh`, `working-memory-read.sh`, `working-memory-write.sh`, `subagent-gate.sh`, `subagent-dispatch.sh`. Cursor's `working-memory-read.sh` runs on `beforeSubmitPrompt` and renders the capsule into `.cursor/rules/working-memory.mdc`, as its `working-memory-write.sh` and `local-context.sh` do at the end of a turn and at session start (steps 6 and 9). All scripts MUST pass `bash -n` and be `chmod +x`. Then write the edition-specific wiring file (below). Append a log to `tasks/TASK-{N}/hook-forge-log.md` listing every hook, its wiring, and the profile evidence backing each danger rule.

## Process

1. **Read the profile.** Confirm selected editions (section 1). Build the context payload from section 2 (framework/version, test/lint/static tools). Build the risk list ONLY from what is present: section 5 (containers/CI/IaC), section 4 (integrations), section 6 (secrets/destructive ops).
2. **Author `bash-validator.sh`** to block only detected risks. Include `php artisan migrate:fresh` / `migrate:rollback` ONLY if that framework's migration tooling was detected; include `kubectl delete` ONLY if Kubernetes was detected in section 5; include `terraform destroy` ONLY if Terraform was detected in section 5. Never block a tool the target does not use.
3. **Author `local-context.sh`** to echo the target's real stack summary at session start (framework, version, key command lines), then run `memory-bank/scripts/context.py status --json` under `timeout "${CONTEXT_HOOK_BUDGET:-5}"` when Python, the CLI, and `timeout` are available. Parse only `automatic_memory.status`, `reason`, and `remediation` with a dependency-free `python3 -c` filter; print at most one bounded warning plus one remediation line when status is `retrieval-only` or `degraded`, print nothing when it is `active`, and discard malformed/failed/timed-out status output. This readiness warning is diagnostic only: the hook MUST always exit 0.
4. **Author `file-naming-validator.sh`** to enforce the target's naming policy (task/spec prefixes, zero-padded task dirs) as stated in the generated policy.
5. **Author `loop-detection.sh`** to detect repeated identical tool calls/edits and warn (warn at 7, block at 10). Track edit counts in a per-repository temp directory namespaced by a stable hash of the repo root (e.g. `TRACK_DIR="/tmp/<tool>-loop-detection-$(printf '%s' "$REPO_ROOT" | cksum | cut -d' ' -f1)"`), so parallel projects never share counters.
6. **Author the working-memory pair** as thin, always-exit-0 callers of `memory-bank/scripts/context.py` (resolve `ROOT_DIR` from the script's own location - `$(dirname "${BASH_SOURCE[0]}")/../..` - never from `$PWD`):
   - `working-memory-read.sh` (the read half; runs at prompt time, writes no task state): skip silently (`exit 0`) when `python3` or the CLI is missing, and when `CONTEXT_CAPSULE_DELIVERED` is `1` (a host such as the Harness already put this turn's capsule into the prompt; a second one would be distilled from that whole prompt); read the hook JSON arriving on stdin with one `python3 -c` program that yields the prompt as-is - distillation into the most informative terms happens in `context.py`, which also screens secrets and personal data - and the conversation's `session_id` only when it matches `[A-Za-z0-9._:-]{1,128}`, and its `transcript_path` only when it is an absolute path (never `sed`-scrape the payload; keep the prompt's own trailing newlines); resolve the task ID from a non-empty `$CONTEXT_TASK_ID`, falling back only to `git symbolic-ref --quiet --short HEAD` (detached HEAD supplies no branch identity); run `context.py refresh`, adding `--query "$QUERY" --task-id "$TASK_ID" --ephemeral --sanitize` only when both are non-empty (`--ephemeral` keeps the per-request manifest in ignored local state; `--sanitize` cuts secrets, personal data and pasted transcript prefixes out of the prompt instead of refusing the turn its memory), plus `--session-id "$SESSION_ID"` when one was read (a conversation is then not handed the same section again within a few turns) and, with it, `--transcript "$TRANSCRIPT"` when one was read (a compaction the host recorded there since the last turn means nothing counts as handed any more); bound the call with `timeout "${CONTEXT_HOOK_BUDGET:-5}"` when `timeout` exists; print the CLI output as-is - the capsule's memory section names itself as reference data to check against the cited file, so no banner precedes it; always `exit 0`.
   - `working-memory-write.sh` (the write half; runs at turn end, where a real delta exists): same python3/CLI/`timeout` guards; require a task ID (a non-empty `$CONTEXT_TASK_ID` or the symbolic Git branch) and exit 0 silently without one; run `context.py turn --task-id "$TASK_ID" --flush-after "${CONTEXT_FLUSH_AFTER:-5}"` with all output discarded; always `exit 0` - a failed checkpoint must never surface as a turn error. An explicit identity outside Git does not make checkpointing available: `turn` requires Git porcelain changed-path metadata. Working-tree contents never reach the buffer.
   - **Cursor read path (Cursor copies only):** Cursor's prompt-time event is `beforeSubmitPrompt`, whose output can only let the prompt through (`{"continue": true}`) or stop it - it cannot add context - so the capsule reaches Cursor through the alwaysApply rule `.cursor/rules/working-memory.mdc`, which Cursor sends with every request. The Cursor copy of `working-memory-read.sh` is wired to `beforeSubmitPrompt`: it sets an EXIT trap that prints `{"continue": true}` on every exit path (memory never blocks a prompt), runs `refresh --host cursor --query "$QUERY" --task-id "$TASK_ID" --ephemeral --sanitize --json` without `--session-id` (the rule is re-sent whole, so nothing may be left out as already handed), takes `capsule_text` from the JSON only when it opens with `working:`, and writes the rule atomically - only when the prompt retrieved an item (a `- ` line, which names the document and the section quoted) the rule it wrote for this task does not hold yet, because Cursor puts rules at the start of the model's context and every change costs the conversation its cached prefix. The Cursor copies of `working-memory-write.sh` (after the `turn` call) and `local-context.sh` (at session start, so a fresh session or branch switch never serves the previous session's capsule) render the branch's capsule into the same rule with `context.py hook-context --host cursor --task-id "$TASK_ID"`, bounded by the same `timeout` budget; the stop render leaves a rule the prompt hook rendered for the same task (its header names the prompt and the task), because rebuilt from the task alone it would lose what was retrieved for the latest prompt - which is what the next request carries when Cursor reads its rules before the prompt hook runs. Every Cursor render stands down when `CONTEXT_CAPSULE_DELIVERED` is `1` (the host already put the capsule into the prompt) and in attached mode. The rendered file MUST carry frontmatter `alwaysApply: true` and a header stating the capsule is not authoritative. When `context.py status --json` reports `retrieval-only` or `degraded`, the session render includes a bounded **Automatic memory readiness** block containing only that status, reason, and remediation; this block must explicitly say checkpoint writes are unavailable when Git metadata is unavailable, even if `CONTEXT_TASK_ID` is set. Write the rule atomically (`mktemp` in `.cursor/rules/`, then `mv` over the rule) and only when a render produced output or a degraded-readiness block is available - a failed empty render keeps the previous rule. The renders are silent on stdout (except the `beforeSubmitPrompt` answer) and never change the exit code. The Claude and Codex copies MUST NOT render this file - they receive the capsule through `working-memory-read.sh` on stdout.
   - **Cursor runs the Claude hooks too** (third-party hooks are on by default, and every matching hook from every source runs). The Claude copies of `working-memory-read.sh` and `working-memory-write.sh` read their stdin payload and exit 0 when it carries `cursor_version` (which Claude Code never sends; an environment variable could leak into a Claude Code session started from Cursor's terminal) and the project has `.cursor/hooks.json`; the Cursor and Codex copies carry no such check. Running both doubled every checkpoint and wrote retrievals nobody received.
7. **Author `subagent-gate.sh` per edition** (tool-owned variants, one contract each):
   - **Claude variant:** self-filter to `tool_name` Agent/Task; extract `tool_input.subagent_type` (jq/php/python3 fallback chain); allow only names found as frontmatter `name:` in the target's `.claude/agents/*.md`; deny everything else with a reason on stderr and exit 2; fail open (exit 0) on missing payload fields or an unreadable roster.
   - **Cursor variant:** `subagentStart` contract - read top-level `subagent_type`, allowlist against `.cursor/agents/*.md` frontmatter names, answer `{"permission":"allow"}` or `{"permission":"deny","user_message":"..."}` on stdout, always exit 0.
   - **Codex variant:** deny the multi-agent tool family (`spawn_agent`, `Agent`, `send_input`, `resume_agent`, `wait_agent`, `close_agent`) unconditionally with stderr + exit 2 - the Codex edition delegates through skills and ships no agents.
   - **Write serialization (Claude and Cursor variants):** when the requested agent's frontmatter carries `writes: true`, take a per-repository lock file before allowing the spawn and deny a second write-capable agent while it is held. Give the lock a TTL (default 30 minutes, overridable by env) so a crashed run cannot deadlock delegation, validate that TTL is numeric before use, and serialize the check-and-take with `flock` where available - parallel spawns arrive in one message and would otherwise both observe an unlocked state. Read the roster from the FIRST frontmatter block only (a `---` rule inside an agent's body must not be able to declare `writes:`). A missing roster, a missing JSON extractor, or an unwritable lock path fails OPEN with a warning on stderr; only a recognized built-in fails closed.
8. **Author `subagent-dispatch.sh`** (one script, all editions): read the stop payload, take the agent name from `agent_type` or `subagent_type` with a structure-aware parser (never a greedy `sed` - a key quoted inside the final message must not shadow the real field), append the completion to the task's channel with `context.py msg-dispatch --task-id <ID> --agent <name> --event complete --note "<one sanitized line>"`, and delete the write lock if this agent holds it. Resolve identity from a non-empty `CONTEXT_TASK_ID`, otherwise from a symbolic branch name; never use the literal detached-HEAD token `HEAD` as a task ID. Always `exit 0`, and degrade silently without `python3`, without the CLI, or without a resolvable task - an observer must never break a turn.
9. **Wire per edition** (identical scripts, different config):
   - **Claude** -> `.claude/settings.json`: `SessionStart` (local-context, timeout 10), `UserPromptSubmit` (working-memory-read, timeout 8), `Stop` (working-memory-write, timeout 8), `PreToolUse` (file-naming-validator on `Write|Edit`, bash-validator on `Bash`, subagent-gate on `Agent|Task`, timeout 5 each), `PostToolUse` (loop-detection on `Edit`, timeout 5), `SubagentStop` (subagent-dispatch, timeout 8), each with a `matcher` where noted and a `timeout` in **seconds**. The same file also carries the configuration half of the gate: `permissions.deny` entries `Agent(Explore)`, `Agent(Plan)`, `Agent(general-purpose)`, `Agent(claude)`, `Agent(statusline-setup)`, `Agent(claude-code-guide)`, plus the `permissions.allow` entry `Bash(python3 memory-bank/scripts/context.py:*)` - the policy tells the agent to read and write memory through that CLI, and without the rule Claude Code asks first in an interactive session and refuses outright under `-p` - plus `env` keys `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS: "1"` and `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH: "1"` - the deny list blocks today's built-ins, the hook covers built-ins added later, and the depth cap keeps orchestration in the main conversation where checkpoints and permissions actually apply. The command form is the script path anchored at the project root through Claude Code's documented placeholder, double-quoted as its shell form requires: `"${CLAUDE_PROJECT_DIR}"/.claude/hooks/<script>.sh`. Claude Code runs a hook in the session's current directory, which follows every `cd` the agent makes, so a bare `.claude/hooks/<script>.sh` exits 127 from any subdirectory - and every exit other than 2 is non-blocking, so the guard silently stops guarding. Claude Code pipes the tool-input JSON to the hook on stdin, so an `echo '$TOOL_INPUT' | <script>` wrapper feeds the hook the literal string `$TOOL_INPUT` instead of the payload and silently disables it.
   - **Cursor** -> `.cursor/hooks.json`: `version: 1`, camelCase events, timeouts in **seconds**: `sessionStart` (local-context, 15), `subagentStop` (subagent-dispatch, 8), `subagentStart` (subagent-gate, 5, with `failClosed: true` - Cursor has no setting that disables its built-in subagents, so this hook is the only enforcement point), `beforeShellExecution` (bash-validator, 5), `afterFileEdit` (file-naming-validator, 5; loop-detection, 5), `stop` (working-memory-write, 15). The two 15s budgets cover the turn flush/session banner plus the capsule render (each inner call is separately `timeout`-bounded). Commands are bare script paths, `.cursor/hooks/<script>.sh` - Cursor runs project hooks from the project root, so the relative path always resolves - with no `bash`/`sh` prefix and no shell wrapper. `beforeSubmitPrompt` (working-memory-read, 8) carries the read half: the Cursor copy renders the capsule for the prompt into the rule from step 6. A `.cursor/cli.json` with `{"permissions": {"allow": ["Shell(python3:memory-bank/scripts/context.py*)"], "deny": []}}` lets the Cursor CLI run the memory CLI the policy names without a prompt. Declare `.cursor/rules/working-memory.mdc` in the task-scoped root-ignore requirements (the rendered rule is transient local state), and record the mechanism in the log and the hooks README.
   - **Codex** -> `.codex/hooks.json`: Claude-style event names, NO `matcher`/`timeout` fields: `SessionStart` (local-context), `UserPromptSubmit` (working-memory-read, with `additionalContextLimit: 4000`), `Stop` (working-memory-write), `PreToolUse` (bash-validator, file-naming-validator, subagent-gate - the gate self-filters to multi-agent tool names), `PostToolUse` (loop-detection). Every command is this one root-finding launcher, verbatim, with only the trailing script name changing: `sh -c 'd=$(pwd); until [ -f "$d/.codex/hooks.json" ]; do [ -n "$d" ] || { echo "$1: no .codex/hooks.json at or above the working directory" >&2; exit 127; }; d=${d%/*}; done; exec "$d/.codex/hooks/$1"' sh <script>.sh`. Codex runs hooks in the session's cwd through the user's login shell (`$SHELL -lc`) and exports no project-root variable, so a bare `.codex/hooks/<script>.sh` exits 127 whenever Codex starts in a subdirectory. The launcher walks from the cwd towards `/` to the nearest directory holding `.codex/hooks.json` - the project that declared the hook - and execs only that project's `.codex/hooks/<script>.sh`, which also covers a project that is not a Git repository and one nested inside a larger repository (where the Git top level is the wrong root). It never looks past that project: a script missing there exits 127 instead of running a same-named script from an ancestor (`~/.codex/hooks/` is Codex's own user-hook directory, `/tmp` is world-writable). Handing the walk to `sh` keeps it independent of the user's shell (fish, zsh, bash). No other wrapper or interpreter prefix. `subagent-dispatch.sh` ships for parity but stays UNREGISTERED here: multi-agent is off, so there are no subagent stops to observe. Plus `.codex/config.toml` containing a top-level `project_doc_max_bytes = 131072` (Codex reads the AGENTS.md chain only up to 32 KiB by default, and the policy block, coming last in a project that has its own AGENTS.md, is what gets cut), `[features]` with `hooks = true` and `multi_agent = false`, and an `[agents]` table with `enabled = false` - the config switches are the hard off-story for Codex built-in subagents; the hook is the backstop for CLI/model combinations that ignore the flags.
10. **Declare root-ignore requirements.** When Cursor is selected, write
    `tasks/TASK-{N}/gitignore-requirements/hook-forge.json` with the exact
    requirement `[".cursor/rules/working-memory.mdc"]`; otherwise write `[]`.
    Never read or mutate the target root `.gitignore`.
11. **Log** every hook, its wiring per edition, the section 4/5/6 evidence that authorized each danger rule, the Cursor read-path exception, the three gate variants, and where the dispatch observer is wired versus shipped unregistered.

## Guardrails

- MUST generate hooks ONLY for the selected editions, each wired through its own mechanism (settings.json / hooks.json / hooks.json+config.toml).
- MUST block a destructive command ONLY when the profile confirms that tool is present (no `terraform destroy`/`kubectl delete`/migration-reset rules without section 5/2 evidence).
- MUST ensure every script passes `bash -n` and is `chmod +x`.
- MUST use second timeouts for Claude and Cursor, and no matcher/timeout for Codex.
- MUST wire every hook in exactly its edition's form from step 9: Claude `"${CLAUDE_PROJECT_DIR}"/.claude/hooks/<script>.sh`, Cursor bare `.cursor/hooks/<script>.sh`, Codex the verbatim root-finding launcher ending in `sh <script>.sh`. MUST NOT wire a bare relative path on Claude or Codex: both run hooks from whatever directory the session is in, the shell exits 127 from a subdirectory, and that exit is non-blocking, so the guard fails open. MUST NOT add any other `bash`/`sh` interpreter prefix or wrapper, trailing shell syntax (`|| true`, `; exit 0`) or quoting of the whole path, and never `echo '$TOOL_INPUT' | <script>`: the payload arrives on stdin, a trailing `|| true` swallows the blocking exit 2, and a wrapper or quoted path can hide a missing hook. bootstrap-verifier matches every command that names a hook against these three forms in full and rejects anything else, and it requires every hook step 9 registers to be wired in its form.
- MUST pass every blocked-pattern regex to `grep` after `--`, and MUST decode the tool-input JSON (jq/php/python3) rather than scraping it with `sed`: a pattern such as `--no-verify` is otherwise read as a grep option, and a `"[^"]*"` scrape truncates any command containing escaped quotes. Both failures exit 0 and silently allow the command.
- MUST make all memory-related hook paths always exit 0. `local-context.sh` may emit only the bounded readiness guidance above; working-memory read/write and dispatch failures remain silent (missing `python3`, missing CLI, no task ID, no Git metadata, timeout). Context tooling must never block a prompt or surface as a turn error. An explicit `CONTEXT_TASK_ID` outside Git enables task-aware retrieval/dispatch only; it MUST NOT be described as enabling `turn` checkpoint writes, which require Git changed-path metadata.
- MUST call the runtime at exactly `memory-bank/scripts/context.py` relative to the target root (the path `memory-seed` creates); MUST NOT inline memory logic into the hooks themselves or write task state from the read hook.
- MUST generate the Cursor `working-memory-read.sh` and wire it on `beforeSubmitPrompt` (step 6): it answers `{"continue": true}` on every exit path and renders the prompt's capsule into `.cursor/rules/working-memory.mdc`. The Cursor copies of `working-memory-write.sh` and `local-context.sh` MUST render into the same rule (frontmatter `alwaysApply: true`, a header stating the capsule is not authoritative, atomic temp-file-then-`mv` replace, previous rule preserved on a failed or empty render, silent on stdout), the stop render MUST leave a rule the prompt hook rendered for the same task, the task-scoped root-ignore requirements MUST declare that file for centralized composition, and the Claude/Codex copies MUST NOT render it.
- MUST NOT read or modify the root `.gitignore`; only
  `infra-generate`/`infra-update` compose approved shared-file changes.
- MUST generate `subagent-dispatch.sh` in every selected edition, wired to `SubagentStop` (Claude) and `subagentStop` (Cursor) and left unregistered on Codex, always exiting 0; it is what releases the write lock, so omitting it strands every write-capable agent until the lock's TTL expires.
- MUST generate `subagent-gate.sh` as three TOOL-OWNED variants (Claude PreToolUse exit codes, Cursor subagentStart permission JSON, Codex spawn_agent-family deny) - never one shared script - and MUST pair the hook with its configuration half: the `Agent(...)` deny list and built-in-agent env keys for Claude, `failClosed: true` for Cursor, `multi_agent = false` plus `[agents] enabled = false` for Codex. The Claude and Cursor gates read the roster from that edition's generated agents' frontmatter `name:` values; a missing or unreadable roster fails OPEN (delegation must not brick), while a recognized built-in fails CLOSED.
- MUST NOT print or log any secret or credential value from the target.
- MUST NOT translate section 8 business invariants, permissions, approvals, or lifecycle rules into brittle shell/text-matching hooks. Behavioral rules belong in policy, skills, tests, review, and memory; hooks enforce only deterministic tool/command/file events.

## Final Output

Return the per-edition hook paths, the wiring file per edition, the evidence-gated danger rules, the `bash -n`/exec-bit results, the log path, and the next step (`memory-seed`).
