# Подробный русскоязычный корневой README

## Цель

Полностью переписать корневой `README.md` на русском языке и сделать его
самодостаточной точкой входа в репозиторий. Новый документ должен объяснять не
только состав трёх PHP-акселераторов и генератора, но и фактически
реализованный локальный Context Engine.

## Аудитория

- PHP-разработчики, выбирающие подходящую редакцию акселератора;
- тимлиды, оценивающие правила работы AI-агентов;
- разработчики, подключающие акселератор к существующему репозиторию;
- участники команды, которым нужно понять границы локальной памяти без чтения
  исходного кода CLI.

## Структура документа

README будет состоять из следующих разделов:

1. назначение репозитория и дерево верхнего уровня;
2. таблица выбора между Laravel, Symfony и PHP Core;
3. варианты подключения акселератора к проекту;
4. общая модель `Command → Agent → Skill`;
5. поддержка Claude Code, Cursor и Codex;
6. отличия трёх редакций;
7. Memory Bank и локальный Context Engine;
8. полный рабочий цикл Context Engine с командами;
9. безопасность, локальность данных и известные ограничения;
10. проверка на реальном Bauherrenmappe;
11. назначение и использование Infrastructure Creator;
12. правила внесения изменений.

## Раздел Context Engine

Раздел должен подробно и простым языком описывать:

- почему Context Engine расширяет Memory Bank, но не заменяет код,
  конфигурацию, тесты, спецификации и политики как источники истины;
- четыре логических слоя в одной локальной SQLite-базе:
  `working`, `procedural`, `semantic`, `episodic`;
- автоматическую классификацию индексируемых источников;
- явный `task-id`, который передаёт вызывающий агент или пользователь;
- допустимые источники `task-id`: номер задачи, имя ветки или понятный slug;
- одновременное хранение нескольких активных задач;
- команды `index`, `start`, `update`, `get`, `context`, `complete`, `clear`,
  `search`, `record` и `status`;
- ограниченную выборку результатов отдельно для каждого долговременного слоя;
- атомарный перевод working-задачи в episode;
- сериализацию конкурентных изменений working-задач через SQLite;
- совместимость старых команд поиска и записи эпизодов;
- хранение списков файлов, источников, следующих шагов и результатов проверки;
- локальное расположение и игнорирование `memory-bank/local/context.db`;
- разницу между пересоздаваемым индексом документов и непересоздаваемыми
  локальными working/episodic-записями;
- отказ от хранения вероятных секретов и запрет на сырые диалоги, промпты,
  ответы, логи, персональные и клиентские данные.

README также должен явно сказать, чего в реализации нет: автоматической
подстановки контекста в каждый запрос, embeddings, vector search, MCP,
LangGraph и центрального сервиса памяти.

## Примеры

Команды будут показаны для запуска из корня выбранной редакции или
потребляющего проекта:

```text
index → start → update → context → complete → search/status
```

Основной пример использует `BAUMAS-133`, реальные относительные пути resolver
и integration test, а также безопасные текстовые результаты проверки. Отдельно
будут объяснены `get`, `clear` и совместимый `record`.

## Проверка на реальном проекте

README будет описывать уже выполненный black-box сценарий на локальном checkout
Bauherrenmappe без заявления о более широкой поддержке:

- найдено четыре индексируемых документа: один procedural и три semantic;
- активная задача прошла через `start`, `update`, `context` и `complete`;
- результирующий episode найден через поиск;
- working-счётчик вернулся к нулю;
- Git-состояние Bauherrenmappe не изменилось;
- база находилась во временном каталоге вне проекта и была удалена.

## Ограничения

- Корневой README не дублирует полные каталоги команд и skills каждой
  редакции: за детальными списками он ссылается на локальные README.
- Документ не обещает автоматизацию, которой нет в CLI.
- Английские названия директорий, команд, слоёв и интерфейсов сохраняются там,
  где они являются фактическими идентификаторами.
- Изменение ограничено корневым `README.md`; README редакций и код Context
  Engine не меняются.

## Проверка результата

После переписывания необходимо:

1. сверить все команды с `context.py --help`;
2. проверить упомянутые пути и ссылки;
3. убедиться, что утверждения о слоях, атомарности и конкурентных обновлениях
   подтверждены текущими тестами;
4. выполнить `git diff --check`;
5. убедиться, что изменён только корневой README, не считая этой спецификации.
