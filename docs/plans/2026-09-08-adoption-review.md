# План: adoption-review — приживается ли установленный акселератор

> Статус: план для будущей реализации, не начат. Решения по развилкам
> зафиксированы 2026-09-08. Основание: разбор `/adoption-review` из
> outstaff-accelerator-kit; закрывает пункт BACKLOG «Economy-2 attribution
> на реальном PHP-проекте → prune skills».

## Проблема

`infra-update` обслуживает файлы; ничто не измеряет, окупаются ли они.
Какие из установленных скиллов/агентов реально вызывались за N сессий,
какие мертвы, какие пользователь отверг — сегодня не отвечает ни один
инструмент. `cost_attribution.py` меряет стоимость, `retrieval-report` —
качество ретрива памяти; ось «adoption» отсутствует.

## Зафиксированные решения

| Развилка | Решение |
| --- | --- |
| Форма v1 | Двухфазная, как у прототипа: детерминированный скрипт-счётчик + скилл поверх, читающий отчёт и сэмплирующий эпизоды для вердиктов. Только скрипт — вердикты из одних цифр (Rejected без цитаты недоказуем); Harness UI — отдельным этапом после v1. |
| Охват v1 | Только транскрипты Claude Code (`~/.claude/projects/<project>/*.jsonl`) — формат уже разобран в `cost_attribution.py`. Cursor/Codex — «not covered» честной строкой в отчёте, не видимостью полноты. |
| Приватность | Санитарно по умолчанию: счётчики + ссылки «сессия+turn». `--quotes` пишет версию с цитатами только в игнорируемую локальную директорию; в git не попадает никогда. |

## Принципы, перенятые из прототипа как есть

- **Четырёхуровневый знаменатель (ревью PR#32).** Каждая единица меряется
  воронкой: **доступность** (могла ли сессия вообще её видеть) →
  **подходящая задача** (был ли повод применить в окне наблюдения: ноль
  вызовов release-скилла за две недели без релизов не значит ничего) →
  **попытка** (сработал ли выбор инструмента) → **полезный исход** (помог
  ли вызов получить проверяемый результат). Opportunity-классификация —
  best-effort, Unknown легален. Частые вызовы сами по себе ≠ польза:
  счётчик не отличает пользу от повторных неудачных попыток — различает
  только чтение эпизодов. Редкие события (релизы, миграции, инциденты) —
  особая интерпретация.
- **Availability before dormancy.** Ноль вызовов в сессиях, где поверхность
  была недоступна (`cwd` вне дерева проекта, правила клиента), — «был
  недоступен», не «не нужен». Без этой проверки аудит врёт.
- **Вердикт не из одних счётчиков.** Used требует доказательства отдачи,
  Rejected — цитаты (или ссылки на неё) «где спорили»; это работа второй
  фазы (скилла), не regex.
- **Unknown — легальный раздел отчёта.** Чего окно измерения не видит,
  то названо, а не замолчано.
- **Блокирующий human gate.** Ни скрипт, ни скилл ничего не правят —
  только ранжированные рекомендации; применение всегда руками.
- **Асимметричное удаление.** Работающий запрет стирает собственные
  доказательства: хук, который блокирует, порождает ноль инцидентов — и по
  счётчикам выглядит «мёртвым». Категория «prohibition» (хуки, запретные
  правила) исключается из prune-рекомендаций по критерию «не срабатывал»;
  для хуков blocked-события считаются отдельной метрикой, а не вызовами.
- **Асимметрия.** Ревьюер живёт в этом репозитории и НЕ входит в
  устанавливаемый payload изданий — иначе мерил бы сам себя. Проверить,
  что инвентори изданий его не подхватывают.
- **Аналог `port-to-kit.md`.** Находки про сам акселератор (не про проект)
  — отдельная секция `upstream` в отчёте; человек переносит их в бэклог
  этого репозитория.

## Наше преимущество над прототипом

`context_budget.py` знает стартовую цену каждого скилла/агента в байтах —
dormant-находка сразу конвертируется в измеренную экономию:
«скилл мёртв за N сессий → прунинг экономит X байт на каждом старте».
У прототипа этой связки нет.

## Шаги реализации

1. **`scripts/adoption_review.py`** (stdlib, по образцу `cost_attribution.py`;
   переиспользуется **обход файлов, не `iter_calls()`** — тот схлопывает
   записи по `message.id` и отбрасывает события без `usage`, теряя как раз
   permission-denied и прерывания (ревью PR#32, P2-3). Нужен отдельный
   event-reader полного потока записей; биллинг-агрегация `iter_calls`
   остаётся для стоимостной оси):
   - вход: `--project <path>` (таргет с установленным акселератором) +
     `--transcripts <dir>` (по умолчанию выводится из пути проекта;
     `--from <dir>` для чужих выгрузок — ревью сборок, установленных до
     появления инструмента);
   - инвентарь измеряемого: скиллы/агенты/команды/хуки из установленного
     payload таргета (`.claude/`, `.agents/`), НЕ из этого репозитория;
   - счётчики по каждой единице: вызовы Skill tool, `subagent_type` в Task
     tool, slash-команды, срабатывания хуков (блокировки в tool results);
   - отказы-кандидаты: denied permission после спавна, прерывания
     пользователем следом за вызовом — **кандидаты, не вердикты**: сами по
     себе не доказывают отвержение, вердикт только из контекста эпизода;
   - availability: `cwd` сессии **внутри дерева проекта** (не строгое
     равенство корню — Claude Code подхватывает корневую поверхность и из
     подкаталога; ревью PR#32, P2-4), правила загрузки — по конкретному
     клиенту и типу поверхности; нехватка данных → Unknown, не ноль;
   - кросс-связка со стартовой ценой из `context_budget.py`
     (байты дескриптора на каждую единицу);
   - выход: `adoption-report.json` + `adoption-report.md` в игнорируемую
     локальную директорию; секции Used-candidates / Dormant / Rejected-candidates
     / Unknown / not-covered (Cursor, Codex); `--quotes` добавляет цитаты
     (локально, никогда в git).
2. **Скилл `adoption-review`** в ЭТОМ репозитории (`.claude/skills/` корня,
   не в изданиях): читает отчёт скрипта, сэмплирует названные эпизоды из
   транскриптов, выносит вердикты Used/Dormant/Rejected с доказательствами,
   ранжирует рекомендации в форме «находка → доказательство → изменение →
   куда падает» (описание/триггер скилла → канон `.agents/skills/`
   таргета; прунинг → с числом экономии; правило → `AGENTS.md` таргета;
   ростер → `settings.json`/subagent-gate). **Лестница рекомендаций**
   (ревью PR#32): сначала правка триггера/содержания, слияние дубликатов,
   загрузка по требованию; удаление — всегда отдельное обоснованное
   решение, последним. Экономия байтов дескриптора показывается отдельно
   от фактической экономии времени/стоимости — это разные величины.
   Prune-рекомендация никогда не предлагается для prohibition-категории
   по критерию «не срабатывал» (см. принцип асимметричного удаления).
   Останавливается на рекомендациях — human gate.
3. **Тесты** — `tests/test_adoption_review.py`: синтетические фикстуры
   транскриптов (вызов скилла, спавн агента, denied, чужой `cwd`),
   счётчики, availability-логика, санитарность отчёта по умолчанию
   (ни одной сырой строки промпта без `--quotes`), «not covered» строки.
4. **Документация** — секция в `docs/OPERATIONS.md` (когда запускать:
   после 2+ недель реальной работы — ориентир запуска, не доказательство
   достаточности данных; интерпретация Dormant vs unavailable vs
   no-opportunity);
   строка в плейбуке внедрения (раздел «Поддержка», п. «измерение
   реального использования» уже ссылается на эту практику).

## Вне объёма v1

- Парсеры Cursor/Codex-транскриптов (v2; отчёт честно помечает пробел).
- События самого Harness как источник (v2): оценка SDD-фаз и `stop_mode`
  по всем провайдерам из одних Claude-Code-транскриптов неполна — harness
  ведёт собственную БД сессий (ревью PR#32).
- Секция в Harness UI (после v1, отдельным этапом в репозитории harness).
- Автоприменение рекомендаций (противоречит human gate по замыслу).
- Запись находок в Memory Bank (сначала посмотреть на реальные отчёты).
